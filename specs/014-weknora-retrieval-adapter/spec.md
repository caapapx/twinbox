# Feature Specification: 可选 WeKnora 检索与长期邮件索引

**Created**: 2026-09-18 | **Status**: Draft — W0–W2 仅完成默认关闭的 fake-provider 本地合同（2026-09-20）；真实 WeKnora、KB/密钥、邮件材料与发布均未实施。  
**Input**: 承接旧 Cursor「008」草案；008 已被企业接口能力占用，本功能使用014，避免旧材料丢失或编号冲突。

## User Scenarios & Testing

### User Story 1 — 授权同步一次，不重复建档（Priority: P1）
管理员启用专用邮件检索空间；主人可在长期材料中找回邮件，不把邮件正文或推断状态变成外部知识权威。
**Independent Test**: 同步、重试、超时、重启和摘录更新后，每个来源身份可对账，无越权文档。

### User Story 2 — 检索后看当前状态与历史未知（Priority: P1）
按业务分类找到有权看的历史材料，命中可回到 TwinBox；当前状态有证据才显示，超出状态窗口显示未知。
**Independent Test**: 分类跨月、无分类覆盖、权限撤回和检索服务不可用均给出真实覆盖与降级状态。

### User Story 3 — 证明有价值才切换（Priority: P2）
管理员对比旧检索和新检索，在召回、延迟、费用、安全与人类操作成本过门后决定是否启用。
**Independent Test**: 固定三十条人工标注查询与安全用例独立评估；关闭新服务后旧链路正常。

### Edge Cases
- Message-ID 缺失/碰撞/复用、同信多文件夹、UIDVALIDITY 变化、账号和租户同名。
- 上传成功但响应丢失、解析未完成、永久失败、映射丢失、限流、权限错误。
- 分类已更新而检索材料未变、pulse已过窗、分类索引无覆盖、删源与撤权。

## Requirements

### Functional Requirements
- **FR-001**: WeKnora 仅为可选检索副本；邮件原文、分类、待办和业务观察继续由其原系统负责；默认关闭且不得阻塞分析。
- **FR-002**: 仅同步授权范围内的稳定身份、必要来源元数据和有界原文摘录；不持久化邮件全文/附件/推断结果/分类标签/规则包/待办状态。
- **FR-003**: 使用租户与账户隔离的稳定身份，区分 Message-ID 候选、文件夹定位和内容冲突；缺失标识及碰撞必须可诊断，不跨账户合并。
- **FR-004**: 内容相同跳过，变化更新；超时后先对账再重试创建，映射丢失可由来源身份重建；并发、重启和删除不得产生失控重复。
- **FR-005**: 索引上传、解析、可检索与失败为不同状态；同步不等待长解析，失败可重试且原因有界，不输出密钥/邮件正文。
- **FR-006**: 检索前约束可信访问范围；结果再验证映射与权限；任何不支持安全隔离的能力不得用后过滤补救泄漏。
- **FR-007**: 分类过滤由 TwinBox 的版本化分类结果提供；跨月覆盖明确，未知不当不匹配；分类改变不重写外部材料标签。
- **FR-008**: 每个命中有来源引用和检索来源；当前状态独立关联，窗口外保持未知；不同模型或检索源得分不可直接混排。
- **FR-009**: 新服务失败时有界超时并回退现有检索；鉴权失败不能扩大权限，回退遵循相同来源授权；关闭开关不损坏旧路径。
- **FR-010**: 专用空间、最小写权限、保留/删除策略、解析状态及接口能力经现场确认后才能用真实材料；确认前只允许本地模拟。
- **FR-011**: 固定三十条查询按关键词、语义及业务分类分组评测，前五条召回不低于旧基线，零越权命中；保留旧索引直到回退门完成。

### Key Entities
- **检索副本**：授权原文摘录及来源定位，不保存动态业务结论。
- **身份映射与同步记录**：来源身份、外部材料标识、内容修订及解析/重试状态。
- **检索命中**：命中来源、证据可见性及可选当前状态。

## Success Criteria
- **SC-001**: 重复、并发和超时故障矩阵中不存在未经对账的重复创建；跨账户/租户数据泄漏为零。
- **SC-002**: 三十条已确认查询的前五条召回总体及各预定分组均不低于旧链路，关键词结果单列。
- **SC-003**: 服务断开、解析失败或关闭开关时邮件分析仍可用，结果明确标注降级/覆盖不足。
- **SC-004**: 真实材料上线前取得授权、隔离及保留策略证据；仅模拟成功不得宣称已接入。

## Assumptions
- 首版只接专用邮件检索空间；跨知识库融合、制度库混写和全文入库不在范围内。
- 如果安全过滤能力不足，保持新检索关闭；这不阻塞其他 TwinBox 与 Agent OS 工作。

## Platform independence — 2026-09-18 clarification

TwinBox是工具与数据载体，本feature属于其自身能力，不是AgentOS通用控制面建设或跨场景业务验证的强制前置。真实业务证据可用于判断是否值得建设长期接入，但不能将邮件类别/身份/协议推广成运维、会议等专业Agent的强制模型。各领域能力仍归专业团队；本次不改变既有功能/安全验收要求，也不授权真实数据写入。
